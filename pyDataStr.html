PHASE 4

Core Data Structures

Programs don't just process instructions — they process data. As the amount of data grows, simply storing values isn't enough. We need efficient ways to organize, access, search, and modify that data. Choosing the right structure can make the difference between a simple, efficient solution and one that becomes unnecessarily slow or complicated.

01. Built-In Collections

1. What Is a Data Structure?

A data structure is a way of organizing and storing data so that it can be used efficiently. Different structures organize data in different ways because different problems require different operations. For example:

  • Need ordered data? → List
  • Need unique values? → Set
  • Need key-value pairs? → Dictionary
  • Need last-in-first-out? → Stack
  • Need first-in-first-out? → Queue

2. Lists — Ordered Collections

Python's list is one of its most commonly used data structures. Lists maintain the order of their elements, allow duplicates, and are mutable (their contents can be changed after creation).

lists.py 
numbers = [10, 20, 30, 40]
print(numbers[0])  # Output: 10

# Modifying and adding
numbers[0] = 100
numbers.append(50)
numbers.insert(1, 15)
numbers.remove(20)
numbers.pop()

3. Tuples — Fixed Collections

A tuple is similar to a list, but it is immutable. Once created, its elements cannot be changed. They are useful when a collection of values should remain unchanged (like coordinate points).

tuples.py 
coordinates = (10, 20)
# coordinates[0] = 50  # This produces an error

4. Sets — Unique Values

A set stores unique values. If duplicate values are added, the set automatically removes them. Sets are excellent for checking existence and for mathematical operations like union (|) and intersection (&).

sets.py 
numbers = {1, 2, 2, 3, 3}
print(numbers) # Output: {1, 2, 3}

a = {1, 2, 3}
b = {3, 4, 5}
print(a | b)  # Union
print(a & b)  # Intersection

5. Dictionaries — Key-Value Data

A dictionary stores information as key-value pairs. Instead of accessing values by position, we access them through their unique keys.

dicts.py 
student = {
    "name": "Alex",
    "age": 20,
    "mark": 85
}

print(student["name"]) # Output: Alex

6. Choosing the Right Python Structure

Structure Ordered Changeable Duplicates Main Idea
List Yes Yes Yes Ordered collection
Tuple Yes No Yes Fixed collection
Set No Yes No Unique values
Dictionary Key-based Yes Keys must be unique Key-value mapping

02. Linear Data Structures

1. Stacks — Last In, First Out

A stack follows the LIFO principle. Imagine a stack of plates: the last plate placed on top is the first one removed. They are heavily used for undo operations, browser history, and function calls.

stack.py 
stack = []
stack.append("A")
stack.append("B")
stack.append("C")

stack.pop() # Removes "C"
C ← Top B A

2. Queues — First In, First Out

A queue follows the FIFO principle, like people waiting in a line. The person who arrives first is served first. Useful for task scheduling and message processing.

queue.py 
from collections import deque

queue = deque()
queue.append("A")
queue.append("B")
queue.append("C")

queue.popleft() # Removes "A"

3. Deques

A deque (pronounced "deck") stands for double-ended queue. It allows elements to be efficiently added or removed from both ends.

deque.py 
from collections import deque
d = deque([2, 3, 4])
d.append(5)       # Add to right
d.appendleft(1)   # Add to left

d.pop()           # Remove from right
d.popleft()       # Remove from left

4. Linked Lists

A linked list stores data in individual nodes, where each node contains its data and a link to the next node. Unlike standard arrays, the elements do not need to occupy consecutive memory locations.

[10 | •] → [20 | •] → [30 | •] → None
node.py 
class Node:
    def __init__(self, data):
        self.data = data
        self.next = None

03. Hierarchical & Non-Linear Structures

1. Trees and Binary Trees

A tree organizes data in a hierarchical structure. The top element is the root. Elements branch downward into parents and children. A binary tree is a tree in which each node has at most two children (left and right).

A / \ B C / \ D E

2. Binary Search Trees (BST)

A Binary Search Tree organizes values according to a strict rule to vastly improve search speeds: values smaller than the root go left, values larger go right. The way data is organized directly reduces the amount of work required to find it.

10 / \ 5 15 / \ / \ 2 7 12 20

3. Graphs

A graph represents relationships between objects. It consists of Vertices (nodes) and Edges (the connections between them). They are essential for modeling road networks, social networks, and task dependencies.

A ─── B │ │ │ │ C ─── D

04. Under the Hood & Mechanics

1. Hash Tables

A hash table is designed for efficient key-based access. Python's dictionary is built on this approach. The key passes through a Hash Function to compute an exact memory location, resulting in incredibly fast lookup times.

Key → Hash Function → Location → Value

2. Mutability

MUTABLE

Objects that can be changed after creation. E.g., Lists, Sets, Dictionaries.

IMMUTABLE

Objects locked at creation. E.g., Integers, Floats, Strings, Tuples, Booleans.

3. References and Objects

Python variables refer to objects in memory; they are not isolated boxes. If multiple variables point to the same mutable object, changes to one reflect in all of them.

references.py 
a = [1, 2, 3]
b = a  # Both refer to the exact same list

b.append(4)
print(a) # Output: [1, 2, 3, 4]

4. Time Complexity

A data structure isn't just about storage; it's about operational efficiency (accessing, searching, inserting, deleting). For example, accessing a list by index (numbers[500]) is extremely fast, but searching for a value (500 in numbers) requires checking multiple elements. We measure this efficiency using Big-O notation.

5. Choosing the Right Structure

Always choose your structure based on how the data will be used. Need unique IDs? Use a set. Mapping students to grades? Use a dictionary. Need strict FIFO processing? Use a queue.

>> THE PRIME DIRECTIVE

Data structures give programs a way to organize information rather than simply storing values randomly. Different problems require different ways of organizing data.
