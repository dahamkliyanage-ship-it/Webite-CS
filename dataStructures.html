Core Data Structures

Programming becomes difficult when data is poorly organized. To write efficient algorithms, we first need to understand how data is structured into three main categories.

1: PRIMITIVE

The foundational data types directly supported by a programming language.

  • Booleans (true/false)
  • Characters (text)
  • Integers (whole numbers)
  • Floating-point numbers (decimal values)
  • References (memory addresses)
  • Enumerated values (predefined choices)

2: COMPOSITE

Also known as data structures, these are built as structured collections of primitive types or other composite types.

  • Array
  • Tuples
  • Union

3: ABSTRACT (ADT)

Mathematical models of data types defined entirely by their behavior as seen by the user.

  • Lists
  • Stack
  • Queue
  • Tree

02. Abstract Data Types (ADTs)

Lists, Tuples, and Dictionaries are built directly into Python. But what happens when you need to engineer a custom data engine? You build an Abstract Data Type (ADT)—a mathematical model of data defined entirely by its behavior as seen by the user.

Linear vs. Hierarchical

Stacks and Queues are linear data structures (elements are explicitly behind or in front of each other). Trees are hierarchical.

The Interface

An ADT hides the internal mechanics. The user only sees the operations they are allowed to perform, like push() or pop().

03. The Stack (LIFO)

A stack is a Last-In/First-Out (LIFO) storage structure. Insertion or removal occurs only at one specific position: the top of the stack. Think of it like a stack of plates—you can only take the top one off.

>> CORE STACK OPERATIONS
  • push(item): Inserts an item to the very top.
  • pop(): Removes and returns the top item.
  • top() / peek(): Returns the top element without removing it, because in a stack, only the top item is visible to an outsider.

04. The Queue (FIFO)

A queue represents a familiar real-world line of people. It is a First-In/First-Out (FIFO) storage structure where insertion happens at the tail, and removal happens at the head.

>> CORE QUEUE OPERATIONS
  • insert(item) / enqueue: Inserts an item at the tail.
  • remove() / dequeue: Removes the item at the front (head).
  • front() & rear(): Returns references to the elements at the head and tail, as those are the only items visible to an outsider.

05. Hierarchical Trees

Most of the data we use in the real world has a hierarchical structure (like a file system or an academic record). A Tree ADT is visualized as an upside-down tree.

The Root

The topmost node of the data structure. It is the single entry point for the entire tree.

Children & Parents

Elements directly under a given element are its children, and the element directly above it is its parent.

Leaves

The terminal nodes at the very bottom of the structure that possess absolutely no children.

Binary Trees

A specific type of tree where every single element has a maximum of exactly 2 children (Left and Right).

06. Tree Traversal

Because trees are not linear, you cannot just iterate from index 0 to 10. You must use recursion to traverse them. The two main strategies are Breadth-First (level by level) and Depth-First (diving to the deepest leaf first).

>> DEPTH-FIRST TRAVERSALS
  • Preorder: Visit Root → Traverse Left → Traverse Right. (Great for creating a direct copy of a tree).
  • Inorder: Traverse Left → Visit Root → Traverse Right.
  • Postorder: Traverse Left → Traverse Right → Visit Root. (Perfect for safely deleting a tree from the bottom up).
