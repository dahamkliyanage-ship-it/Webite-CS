PHASE 5

File Handling & Robustness

A program doesn't always work with data that exists only while the program is running. Real applications need to save information, load existing data, communicate with files, and deal with unexpected situations. Welcome to anticipating chaos. This phase covers file handling and robustness — the skills that turn a simple script into code that can reliably work with real-world data and survive without crashing.

01. Basic File Operations

1. What Is File Handling?

File handling allows a program to interact with files stored on a computer, enabling information to persist beyond a single program execution. Data can be created, read, written, appended, and modified.

2. Opening and Reading Files

Python provides the open() function for working with files. The first argument specifies the file, while the second specifies the mode (e.g., "r" for read, "w" for write, "a" for append).

reading.py 
file = open("notes.txt", "r")
content = file.read()
print(content)
file.close()

# Reading line by line is more memory-efficient:
with open("notes.txt", "r") as file:
    for line in file:
        print(line.strip())

3. Writing and Appending

The "w" mode allows you to write data to a file, completely overwriting its existing contents. If you want to add new data without erasing the old (like in logs or user records), use the "a" (append) mode.

writing.py 
# Overwrites existing data
with open("notes.txt", "w") as file:
    file.write("Hello, Python!")

# Appends to existing data
with open("notes.txt", "a") as file:
    file.write("\nNew note")

4. The with Statement

One of the most important habits in file handling is using the with statement (a context manager). It automatically handles closing the file when the block finishes, preventing memory leaks and locked files.

02. Paths & Structured Formats

1. Working with File Paths

Files aren't always located in the same folder as your Python program. Python's pathlib module provides a clean, cross-platform way to work with paths and directories.

paths.py 
from pathlib import Path

folder = Path("data")
if not folder.exists():
    folder.mkdir()

file_path = folder / "users.txt"
if file_path.is_file():
    print("File found.")

2. CSV and JSON Files

Real-world data is structured. CSV (Comma-Separated Values) files are commonly used for tabular data (rows and columns). JSON (JavaScript Object Notation) is used for configuration files, APIs, and complex hierarchical data.

read_csv.py 
import csv

with open("data.csv", newline="") as f:
    reader = csv.reader(f)
    for row in reader:
        print(row)
write_json.py 
import json

student = {"name": "Kamal", "age": 20}
with open("data.json", "w") as f:
    json.dump(student, f, indent=4)

03. Error Handling & Exceptions

1. Handling Exceptions with try and except

Programs don't always execute successfully. If a user enters text when a number is expected, Python raises a ValueError. Instead of allowing an unexpected error to crash the program, we can handle it using specific exceptions.

safe_input.py 
try:
    number = int(input("Enter a number: "))
except ValueError:
    print("Invalid number. Please try again.")

2. else and finally

The else block runs only if no exception occurs. The finally block runs regardless of whether an exception occurred (useful for cleanup actions).

try ↓ Did an error occur? ↙ ↘ Yes No ↓ ↓ except else \ / finally

3. Handling File Errors

Files introduce many possible problems. Attempting to read a file that doesn't exist raises a FileNotFoundError. Catching multiple specific exceptions makes your program significantly more robust.

04. Defensive Programming & Architecture

1. Raising and Custom Exceptions

Sometimes your program needs to identify invalid situations itself using the raise keyword. For larger programs, creating custom exceptions makes the error communicate exactly what went wrong.

custom_error.py 
class InsufficientFundsError(Exception):
    pass

def withdraw(balance, amount):
    if amount > balance:
        raise InsufficientFundsError("Not enough funds.")
    return balance - amount

2. Input Validation & Defensive Programming

Robust programs don't blindly trust user input. Never assume that external input is valid. Defensive programming means writing code with the expectation that things will go wrong. Validate input using while True loops and try-except blocks until acceptable data is received.

3. Logging

When programs become larger, print() isn't enough. Python's logging module records execution data across varying levels of severity: DEBUG, INFO, WARNING, ERROR, and CRITICAL.

4. The Bigger Picture

By combining file handling, input validation, and exception management, your software moves beyond fragile scripts into reliable architecture that survives real-world chaos.

User ↓ Input / Request ↓ Validate the data ↓ Process the data ↙ ↘ Success Error ↓ ↓ Save data Handle error ↓ ↓ File / JSON Log it ↓ Continue
